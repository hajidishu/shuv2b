# 支付后的前端回跳

## 配置步骤

在「系统配置 → 站点」设置，无需数据库迁移：

| 配置 | 填写方式 |
| --- | --- |
| 支付回跳前端地址 | 完整 HTTP(S) 地址，可带子目录；留空用站点网址，再为空用当前请求站点 |
| 支付回跳路径模板 | 默认 `/#/order/{trade_no}`，EZ Theme 可用 `/#/payment?trade_no={trade_no}`；必须有且只有一个 `{trade_no}` |
| 支付回跳允许域名 | 多前端时填写额外来源，如 `https://panel2.example.com`；精确匹配协议、域名与端口，不支持通配符 |

例如地址 `https://panel.example.com/customer`，模板 `/#/payment?trade_no={trade_no}`，订单 `123` 将返回：

```text
https://panel.example.com/customer/#/payment?trade_no=123
```

保存后重新生成付款链接验证，旧链接不会改动。`{trade_no}` 使用用户订单号。

## 常见问题

**多个前端如何选择？** 请求 Origin（没有时取 Referer 来源）匹配允许项后使用该来源，否则用配置地址。各来源共用路径模板。

**子目录如何处理？** 配置地址的子目录会保留，额外允许来源从根路径拼接。多前端共用子目录时，把子目录写进模板，前端地址只填来源。

**会改变支付通知吗？** 不会。异步通知仍指向后端，验签后确认收款；回跳只负责浏览器导航。

**CoinPayments 为何返回首页？** 成功后保持返回前端首页，保留子目录；取消后返回配置的订单页面。
