# 支付

## 添加支付方式

在「支付配置」选择接口文件，填写商户参数，保存并检查通知地址后启用。通知路径需能被支付平台访问，关闭该路径的人机挑战。

| 地址 | 用途 |
| --- | --- |
| 异步通知 `notify_url` | 支付平台向后端发送收款结果，验签后结算 |
| 回跳 `return_url` / `success_url` | 浏览器返回用户前端，不负责确认收款 |

前后端分离时，在「系统配置 → 站点」设置[回跳地址及路径](../features/payment-return-url)。默认路径为 `/#/order/{trade_no}`，EZ Theme 等可用 `/#/payment?trade_no={trade_no}`。

## 查看收款

订单详情可查看收款及补充入账。取消后迟到、或已开通后的额外收款会按规则转入用户余额，重复通知不会重复入账；这不是原渠道退款。详见[支付台账](../features/payment-ledger)。

## 添加支付插件

适配器放在 `app/Payments`，实现配置、付款创建及通知验证，并接入付款尝试与收款校验。验证金额单位、币种、签名、商户及订单归属、通知幂等；Stripe 需按币种最小单位处理。

## 常见问题

**已付款但未开通？** 按顺序检查商户账单、通知送达及验签、订单台账、Horizon 的 `order_handle` 队列。

**付款后跳错页面？** 核对主题路由与回跳设置，生成新的付款链接；已发出的旧链接不会随配置改变。
