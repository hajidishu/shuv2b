# 支付尝试与收款处理

## 收款规则

每次付款尝试使用独立商户订单号，用户订单号不变。同配置、同参数在一分钟内复用链接，之后可生成新链接；切换通道不覆盖旧尝试，迟到通知仍可识别。

- 首笔通过校验的有效收款正常开通，同通道交易号只处理一次。
- 订单已取消，或已由另一笔付款开通时，额外收款按该次人民币报价全额（含手续费）转入用户余额，不重复开通、返佣或赠金。
- 在管理员订单详情「补充收款已转入余额」查看金额、原因与时间；这是站内余额入账，不是原渠道退款。

金额和币种按付款时保存的报价校验。Stripe 使用目标币种最小单位，重试沿用冻结报价。

## 通道与密钥

历史网关配置以 `APP_KEY` 加密保存。**保留并备份原 `APP_KEY`**，更换前需迁移加密数据。

有付款历史的通道应停用，不直接删除；停用阻止新付款，已有尝试仍能验签结算。空密钥不可启用，BEPUSDT / Epusdt 使用自签证书时需配置可信 CA。

## 安装与升级

正常安装、`php artisan v2board:update` 自动创建 `v2_payment_attempt`、`v2_payment_receipt`。单独安装：

```sh
php artisan payment-ledger:install
php artisan config:cache
php artisan horizon:terminate
```

升级前备份数据库、配置和密钥，之后重载 Web 进程，确认 Horizon 恢复。重复安装不会清空台账。

## 常见问题

**旧付款链接还能结算吗？** 按原绑定通道处理；升级前已被覆盖、没有历史记录的通道无法重建，需按商户账单对账。

**取消订单会恢复优惠券额度吗？** 有限配额会幂等释放；旧版已取消但丢失的历史额度不自动补回。

**能直接回退旧代码吗？** 先停新付款并处理在途尝试。旧代码不识别新商户订单号，两张台账表应保留用于对账。
