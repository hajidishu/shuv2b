# 人工内鬼排查

在「用户 → 内鬼排查」创建固定 A/B 分组，按人工检测结果逐轮缩小候选范围。系统不自动检测封锁或封禁用户。

## 操作步骤

1. 准备两个可用、可独立观测的节点入口，在「专用节点池」登记。无需让用户拥有其权限组；不要使用营业节点或共用地址 / 父节点的入口。
2. 点击「新建任务」，按有效套餐用户、指定套餐、邮箱或组合筛选选择名单，再选择两个空闲入口。
3. 确认预览后创建。名单冻结并随机均分 A/B，每人保留正常节点，额外获得所属组节点；同一轮分组不变。
4. 人工检测并记录两组结果。只有一组「人工确认异常」、另一组「正常」时，才能选择异常分支继续排查。
5. 推进时可复用本轮节点或选择其他空闲节点。候选超过一人时再次均分，只剩一人时结束并展示邮箱；其他结果可继续观察、暂停或结束。

观察周期仅作提示，不强制等待；未拉取的账号不会自动排除，候选结果不等于违规证据。

## 节点池与授权

- 登记后立即停止普通订阅下发和普通权限组授权，仅授权当前活动轮次成员；未分配时不授权用户。
- 用户仍需满足有效套餐、有效期、剩余流量、封禁及限速 / 设备等约束。普通节点权限不变。
- 同一用户只能参加一个进行中或暂停任务。暂停继续占用节点，结束后节点恢复可用，可反复使用；移出池会恢复原权限组可见范围。
- 修改活动入口的地址、端口、协议、父节点或显示状态，会停止匹配原快照的下发与授权，需核查后继续。
- 节点端需重新拉取用户名单；暂停或结束不会清除客户端已保存的配置，也不保证旧连接立即断开。

## 查看下发与历史

「已返回节点人数」仅统计实际生成节点并返回 200 的请求；不支持协议、失败和 304 不计入。它证明配置已返回，不代表实际连接。

任务详情可查看轮次、成员、检测结果与下发记录，并关联订阅审计。结束历史默认保留 **90 天**，可用 `LEAK_PROBE_HISTORY_DAYS` 调整；节点池登记不随历史删除。

## 安装与升级

正常安装、`php artisan v2board:update` 自动补齐六张 `v2_leak_probe_*` 表。单独安装：

```sh
php artisan leak-probe:install
php artisan config:cache
php artisan horizon:terminate
```

保留 Horizon 守护、`subscription_audit` 消费者和每分钟调度；历史由 `leak-probe:prune` 每日清理。常驻 Web 进程需重启。

## 常见问题

**旧版退役节点还能用吗？** 升级会恢复可用状态，保留历史和活动占用。复用前人工确认入口仍可用。

**第三方服务端如何适配？** 调用 `ServerService::getAvailableUsers()` 时传入权限组、节点类型和 ID。新增订阅格式需在实际生成节点时调用 `LeakProbeService::renderedValue()` 记录下发。

**如何停用或回退？** `LEAK_PROBE_ENABLED=false` 停止排查下发与授权，节点池仍隔离。回退到无此功能的代码前，先结束任务、停用专用入口或清空权限组并确认节点端同步，不能只隐藏节点。
